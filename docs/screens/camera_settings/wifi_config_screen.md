# WifiConfigScreen

- **Dart file:** `lib/screens/camera_settings/wifi_config_screen.dart`
- **Route:** `/dashboard/live/:cameraId/settings/info/wifi-config`
- **Purpose:** Reached from the "Configure Wi-Fi" button (CAMINFO-029) on [camera_info_screen.md](camera_info_screen.md). Two independent real data sources, not one: (1) the **camera's own current network**, from `camera_api` (`OnvifDeviceClient.getNetworkInterfaceInfo` to detect wired vs. wireless, `NetworkInfoClient.getWifiSsid`/`.getWifiSignalStrength` for the current SSID/signal) — falls back to local-only `HomesController` state (`simulateCameraSave`) when the camera has no saved connection; and (2) **nearby networks the phone itself can see**, via the `wifi_scan` plugin (Android only — see Notes), which has nothing to do with `camera_api`. Switching the camera to a new network (`NetworkInfoClient.setupWifi`) is one form fed by either source.

## Notes

- **Two unrelated "Wi-Fi" concerns share this screen — don't conflate them.** The camera's current network (WIFI-010/011) and the "change network" form (WIFI-007/008/009) talk to the *camera* over `camera_api`. The nearby-networks list (WIFI-012–016) talks to the *phone's own* Wi-Fi radio via the `wifi_scan` plugin — it has nothing to do with `camera_api`/`NetworkInfoClient`, which has no scan-for-nearby-networks capability of its own. Selecting a WIFI-013 row is purely a convenience to prefill WIFI-007; it never calls anything camera-side by itself.
- **Real nearby-network scanning is Android-only — iOS has no public API for it.** Android ties Wi-Fi scan results to a grantable location permission (`ACCESS_FINE_LOCATION`, requested via the plugin's own `askPermissions: true`), which is invasive but at least possible. iOS gives third-party apps no way to enumerate nearby SSIDs at all (only the currently-connected network, via a special entitlement this app doesn't have), so there is no iOS equivalent to build — WIFI-016 explains this rather than showing an empty/broken list. Platform check is `defaultTargetPlatform == TargetPlatform.android`, not `dart:io`'s `Platform.isAndroid`.
- **Retired:** `WIFI-003` (old scanned network list), `WIFI-004`/`WIFI-005` (old per-network password field/Connect button), `WIFI-006` (old "Edit manually" toggle) — belonged to an earlier fully-stubbed version of this screen that faked a scan with a hardcoded list before either real data source (camera-side or phone-side) existed. Do not reuse these IDs.
- A camera with no saved connection (`Camera.connection == null`) skips WIFI-002/010/011 (nothing to load camera-side) but still runs the WIFI-012–016 phone-side scan normally, since that doesn't depend on the camera at all. Connect falls back to `simulateCameraSave` + the same local-only persistence, matching every other camera-settings screen's no-connection fallback.
- `setupWifi`'s `verify` parameter (default `true`, meaning "save and attempt to connect") isn't currently exposed as a separate UI toggle — every Connect tap here uses the default.
