# DangerZoneScreen

- **Dart file:** `lib/screens/camera_settings/danger_zone_screen.dart`
- **Route:** `/dashboard/live/:cameraId/settings/danger-zone`
- **Purpose:** Reached from the "Danger Zone" row on [camera_settings_screen.md](camera_settings_screen.md). Offers Soft Reset, Reset Settings, and Factory Reset (grouped together — all three require the camera to be online, since they round-trip to the device) and Delete Camera (its own group, allowed even while offline — it only removes the camera from local app state, no device round-trip needed). The three device actions map onto `OnvifDeviceClient`'s real surface — `reboot()` (DANGER-004) and `factoryReset(FactoryResetMode.soft/.hard)` (DANGER-005/DANGER-007) — retried over `WanDeviceIdentityClient` if the LAN call fails and `connection.thingName` is known, per `.claude/rules/mobile-app-screen-conventions.md`'s LAN/WAN convention. Falls back to `simulateCameraSave` (local-only, ~800ms, always succeeds) for a camera with no saved connection yet.

## Elements

| Design ID | Element | Type | Notes |
|-----------|---------|------|-------|
| DANGER-001 | Screen title (AppBar) | Text | "Danger Zone" |
| DANGER-003 | Warning intro text | Text | "These actions are destructive and, in most cases, cannot be undone. Proceed with care." |
| DANGER-004 | Soft Reset tile | `_DangerTile` (local widget) inside a `GlassCard`, grouped with DANGER-005/DANGER-007 | disabled (dimmed, "Camera is offline — reconnect it to reboot." subtitle) when `!camera.isOnline`; otherwise shows "Reboots the camera. Settings and recordings are kept." Tapping opens a confirm dialog ("Reboot camera?" / Cancel / Reboot); on confirm shows the full-screen `SavingOverlay` (label "Rebooting…") while calling `OnvifDeviceClient.reboot()`, then a "Camera is rebooting" snackbar, or a failure snackbar. Per `reboot()`'s own doc: the call succeeding doesn't mean the device is back yet — expect a real connectivity gap of several seconds afterward |
| DANGER-005 | Reset Settings tile | `_DangerTile`, grouped with DANGER-004/DANGER-007 | disabled the same way as DANGER-004 when offline; otherwise shows "Erases camera settings and restores factory defaults. Wi-Fi stays connected. This cannot be undone." Confirm dialog ("Reset settings?" / Cancel / Erase & Reset); on confirm shows `SavingOverlay` (label "Resetting…") while calling `OnvifDeviceClient.factoryReset(FactoryResetMode.soft)` — erases ONVIF settings (imaging, masks, OSD, etc.) but **keeps WiFi credentials**, camera stays reachable on this network afterward — then a "Camera settings have been reset to factory defaults" snackbar, or a failure snackbar. Renamed from "Hard Reset" — same tile/key, corrected to describe what `FactoryResetMode.soft` actually does rather than the ambiguous prior wording |
| DANGER-007 | Factory Reset tile | `_DangerTile`, grouped with DANGER-004/DANGER-005 | disabled the same way as DANGER-004 when offline; otherwise shows "Erases everything, including Wi-Fi credentials — the camera disconnects from this network and needs full re-onboarding. This cannot be undone." Confirm dialog ("Factory reset camera?" / Cancel / Erase Everything) spells out the same consequence in full before the user can proceed; on confirm shows `SavingOverlay` (label "Factory resetting…") while calling `OnvifDeviceClient.factoryReset(FactoryResetMode.hard)` — erases ONVIF settings **and** WiFi credentials, camera re-enters AP provisioning mode and needs to be fully re-onboarded (WiFi re-entered, WS-Discovery/manual add repeated) — then a "Camera has been factory reset — reconnect it to the network to use it again" snackbar, or a failure snackbar. New tile, added alongside DANGER-005 once the distinct Soft/Hard `FactoryResetMode` split was found in `packages/camera_api` — the screen previously only exposed one factory-reset-style action even though the real API has two meaningfully different ones |
| DANGER-006 | Delete Camera tile | `_DangerTile` inside its own `GlassCard`, visually separated from the reset group | always enabled, even when the camera is offline — deleting doesn't need to reach the device. Confirm dialog ("Delete camera?" / Cancel / Delete); on confirm calls `HomesController.deleteCamera` (removes the camera from its home's camera list) and navigates to [dashboard_screen.md](../dashboard/dashboard_screen.md) via `context.go`, since the camera the user was viewing no longer exists |

DANGER-002 (previously a "coming soon" placeholder message) is retired — replaced by real content above.
