# AiModeScreen

- **Dart file:** `lib/screens/camera_live/ai_mode_screen.dart`
- **Route:** not a go_router route — pushed via `Navigator.of(context, rootNavigator: true).push(MaterialPageRoute(...))` from Camera Live's `_openAiMode`, the same `rootNavigator: true` reasoning `_openFullscreen` (LIVE-008) already uses: Camera Live sits inside a `StatefulShellRoute` branch with its own nested Navigator, so a normal nested `GoRoute`/`context.push` would keep `MainShell`'s bottom nav bar visible underneath AI Mode instead of taking over the whole screen (this is exactly what happened before this was fixed — the bottom nav bar was bleeding through and overlapping the bottom of the chat). Camera Live stays alive underneath, popped back to on close
- **Purpose:** Look-and-feel prototype of a Google Circle-to-Search-style AI assistant for the live view. The user circles/scribbles a rough loop around an object on a frozen frame, or just taps it; after a brief "Detecting object…" beat the gesture snaps into an **adjustable bounding box** — reusing `ZoneOverlay` (`lib/widgets/drawable_zone.dart`), the same draggable/resizable rectangle-with-corner-handles widget the Privacy Zone and motion-detection zone editors already use — that the user can drag or resize before asking a question, or pick a "lost item" preset instead. Asking **crops exactly the boxed pixels out of the frame** (real crop, via `dart:ui` canvas drawing — not a stub), adds that cropped snippet to a chat turn alongside the question and (once it arrives) the answer, and **the frame/box view itself disappears the instant you ask**, handing the whole screen to the chat — matching Circle to Search's own behavior of the results panel taking over once you've circled something, rather than leaving the frame permanently docked above a half-height chat. AIMODE-022 brings the frame back to select a different object; existing chat turns stay put underneath. **No real AI backend, and no real object segmentation, is wired up yet**: the box is just the drawn gesture's bounding rect (or a fixed-size box centered on a tap), the crop is real pixels but nothing analyzes them, and asking always returns a canned stub reply — same stubbing convention as Camera Live's Talk/Spotlight tiles. (The Dashboard's own chatbot FAB, DASH-020, previously used an on-device Qwen model via `llamadart` — that dependency and its chat UI have since been removed; this screen never depended on it and is unaffected, but the backend plan referenced here is no longer current.) Entered via Camera Live's LIVE-043 tile, which captures the current frame (reusing `_captureFrame`, the same `RepaintBoundary`-based capture LIVE-009's snapshot uses) and passes it in as `AiModeLaunchArgs`, along with a `captureFrame` callback so AIMODE-006 can grab a fresh frame without a second round trip through Camera Live.

## Elements

| Design ID | Element | Type | Notes |
|-----------|---------|------|-------|
| AIMODE-001 | Screen title (AppBar) | Text | "AI Mode"; `backgroundColor`/`foregroundColor` forced to black/white rather than inheriting the app theme, since this screen otherwise renders on a black background — the default theme's AppBar text/icon color read as low-contrast (near-invisible) against it |
| AIMODE-002 | Close button | IconButton (AppBar leading) | pops back to Camera Live |
| AIMODE-003 | Frozen frame | `Image.memory` inside a `LayoutBuilder`/`Stack`, wrapped in a `Center`+`AspectRatio(16/9)` | the frame captured on entry (or by AIMODE-006); `BoxFit.cover` (not `.contain` — chosen so the displayed frame always exactly fills the gesture/box area, which `_cropFrame`'s scale/offset math and `ZoneOverlay`'s 0-1 fractional rect both assume). The 16:9 constraint matches Camera Live's own video `AspectRatio` (`camera_live_screen.dart`) rather than letting the frame stretch to whatever height its `Expanded` happens to get — the `LayoutBuilder` sits *inside* the `AspectRatio` so `_frameAreaSize` (and therefore the gesture/box/crop math) measures the actual 16:9 box, not the wider `Expanded` around it. Its containing `Expanded` uses `flex: 3` against the chat panel's `flex: 5` (a fixed bug: they were originally `flex: 5` vs. an unset default `flex: 1`, so the panel below only ever got 1/6 of the screen), and is omitted from the `Column` entirely (not just hidden/zero-height) once `_frameCollapsed` is true, so the chat panel is the only `Expanded` left and naturally fills the full screen |
| AIMODE-004 | Circle/tap-select gesture | `GestureDetector` (pan + tap) over the frame, only present while nothing's selected yet | drag draws a rough loop (thin live line while dragging); a single tap creates a fixed-size (22% of the frame) box centered on the tap instead. Either way, releasing hands off to a brief "Detecting…" beat (AIMODE-018) before the gesture's bounding rect becomes the adjustable box below |
| — | Adjustable selection box | `ZoneOverlay` (shared widget, not a new design ID — same component as the Privacy Zone/motion-zone editors) | appears once detection finishes; drag the box to move it, drag a corner handle to resize; replaces AIMODE-004's gesture area until cleared |
| AIMODE-005 | Clear selection button | IconButton, top-right over the frame | shown once a selection/box exists (or a drag is in progress); clears it and cancels any pending detection, re-enabling AIMODE-004 to draw a new one. Doesn't touch existing chat history |
| AIMODE-006 | Retake frame button | IconButton, top-right over the frame | re-captures a fresh frame via the `captureFrame` callback passed from Camera Live; shows a loading overlay while in flight; clears any current selection (not chat history — earlier turns keep their own already-cropped snippets, which were cut from whatever frame was live at the time) |
| AIMODE-007 | Ask panel | `Column` below the frame, standard chat-app order: chat history **fills the remaining space at the top** (`Expanded`), preset picker + question input are fixed-height and **pinned at the very bottom** | earlier version had input/presets on top and history squeezed below, which — combined with the old bottom-nav-bleed bug — pushed a turn's cropped-image thumbnail and answer out of the visible area; reordering to history-fills/input-pinned is the standard chat layout and fixes that regardless |
| AIMODE-008 | Question text field | TextField, bottom row | "Ask about the boxed area…" once a box exists, else "Ask a question…"; if left empty while a box exists, the implicit question is "What is this?" (mirrors Circle to Search's default-query behavior) |
| AIMODE-009 | Ask/Send button | IconButton (send icon), bottom row | the one confirm step for every path (box, preset, or typed question) — adjusting the box itself doesn't auto-ask, since it's meant to be nudged into place first. Sets `_frameCollapsed = true` immediately (before the crop/answer even resolve — the panel hands over to full-screen chat right away, not once the answer lands), crops the current box (if any), and appends a new chat turn. Disabled until there's text, a preset/custom item, or an active box, and while the last turn is still awaiting its answer |
| AIMODE-010 | "Lost item:" label | Text, inline with AIMODE-011 | short label so the preset row reads as one compact line rather than its own section, given it now shares bottom-pinned space with the input row |
| AIMODE-011 | Preset item chips | `ChoiceChip`s in a single horizontally-scrolling row (`ListView`, not `Wrap`) | Pen, Book, Laptop, Keys, Wallet, Phone, Bag, Other; tapping the already-selected chip deselects it; horizontal-scroll (rather than wrapping to multiple rows) keeps this row's height fixed regardless of screen width |
| AIMODE-012 | Custom item text field | TextField, shown only when the "Other" chip is selected | free-text item name, feeds the same stub question flow as a preset pick |
| AIMODE-013 | Chat history list | `ListView.builder`, one turn per `_ChatEntry`, in the `Expanded` top section | auto-scrolls to the newest turn on send and once its answer lands |
| AIMODE-014 | Per-turn loading row | Spinner + "Thinking…" text, inside a turn | shown in place of AIMODE-021 for whichever turn is still awaiting its stub answer (~0.9s after send) |
| AIMODE-015 | Empty state | `Column` (hint text + AIMODE-023), centered in the chat area | shown only before the first turn exists |
| AIMODE-016 | Mic button | IconButton, left of AIMODE-008, bottom row | stub — matches `CHAT-013`'s pattern exactly: shows a listening state for 2s then a snackbar ("Voice input isn't available yet"); no `speech_to_text` package added yet |
| AIMODE-017 | Drag/detect scrim | `AnimatedOpacity` dark overlay over the whole frame | fades in while actively dragging AIMODE-004's gesture and during the AIMODE-018 detection beat, fades out once the box appears — echoes the screen-dim Circle to Search shows while its overlay is active |
| AIMODE-018 | "Detecting object…" row | Spinner + text, between the chat list and the bottom input section, plus a small spinner centered on the frame | shown for the fixed `_detectionDelay` (~500ms) between a gesture ending and its bounding rect becoming the adjustable box — a distinct beat from AIMODE-014's per-turn "Thinking…", so instant object detection reads as separate from actually answering a question |
| AIMODE-019 | Cropped snippet thumbnail | `Image.memory`, top of a chat turn (user side), only when that turn had an active box | the actual cropped pixels cut from the frame at ask-time via `_cropFrame` — real image data, not a placeholder |
| AIMODE-020 | Question bubble | Right-aligned chat bubble, per turn | the resolved question text (typed, preset, or the implicit "What is this?") |
| AIMODE-021 | Answer bubble | Left-aligned chat bubble, per turn | the stubbed answer once it lands; replaced by AIMODE-014 while pending |
| AIMODE-022 | "Select another object" button | IconButton, AppBar action | only shown once `_frameCollapsed` is true (i.e. after at least one turn's been sent); brings AIMODE-003's frame view back, clears the current box/drag so a fresh one can be drawn, and leaves existing chat history untouched below |
| AIMODE-023 | Suggested-question chips | `ActionChip` `Wrap`, inside AIMODE-015 | example questions beyond the "lost item" flow — "What is this object?", "Who is this person?", "When did they arrive?", "Track this person", "Is this a delivery?" — tap-to-send: tapping one fills AIMODE-008 and asks immediately, disappears once the first turn exists (empty-state only) |
