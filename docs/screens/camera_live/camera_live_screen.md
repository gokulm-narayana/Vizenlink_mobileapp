# CameraLiveScreen

- **Dart file:** `lib/screens/camera_live/camera_live_screen.dart`
- **Route:** `/dashboard/live/:cameraId` (nested as a child route of the Dashboard branch inside the bottom-nav `StatefulShellRoute`, so the bottom nav bar stays visible here and throughout the whole Camera Settings sub-tree; see [navigation_flow.md](../navigation_flow.md))
- **Purpose:** Show a single camera's live feed with playback-style controls, and a secondary "Playback" tab for reviewing recorded footage. No CCTV protocol (RTSP/ONVIF/etc.) has been chosen yet, and no recordings backend exists yet — the video area currently plays a bundled 15-minute dummy sample clip (`assets/videos/camera_dummy.mp4`) via the `video_player` package as a stand-in for both tabs (see CLAUDE.md). Snapshot (LIVE-009) and Record (LIVE-010) are real, not stubs: snapshot captures the actual on-screen video frame and record saves a video file, both via the `gal` package into the device photo gallery. Recorded content is the dummy asset trimmed (via `ffmpeg_kit_flutter_new`) to match how long the user actually recorded, standing in for a real capture since there's no real stream yet. Takes `homesController` and looks up the live `Camera` by id on every rebuild (via `ValueListenableBuilder`) instead of using a static navigation snapshot, so settings changed elsewhere (e.g. On-Screen Display's OSD toggles) are reflected immediately without leaving this screen. Also tracks the *phone's* own network type via `connectivity_plus` (LIVE-038/039/040) — a real, live-updating signal, independent of the camera's own Wi-Fi status shown elsewhere on this screen (LIVE-030).

Playback clip handles (LIVE-023/LIVE-024) are not guarded on leave — they're low-stakes scratch state and are simply lost if the user navigates away before extracting.

LIVE-004/LIVE-037/LIVE-029/LIVE-030 are computed together by `_buildOsdTags` (private helper on `_CameraLiveScreenState`): if two or more of these four tags land on the same corner, `osdStackIndices` (`lib/widgets/live_status_badges.dart`) lines them up side by side, growing inward from that corner's horizontal edge — in Live tag → audio-recording indicator → Bitrate → Signal Strength priority order — instead of letting them render on top of each other.
