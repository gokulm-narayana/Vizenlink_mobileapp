# CameraLiveScreen

- **Dart file:** `lib/screens/camera_live/camera_live_screen.dart`
- **Route:** `/dashboard/live/:cameraId` (nested as a child route of the Dashboard branch inside the bottom-nav `StatefulShellRoute`, so the bottom nav bar stays visible here and throughout the whole Camera Settings sub-tree; see [navigation_flow.md](../navigation_flow.md))
- **Purpose:** Show a single camera's live feed with playback-style controls, and a secondary "Playback" tab for reviewing recorded footage. **Live tab video is real** for any camera with a saved LAN connection: `LiveViewController` (`lib/app_state/live_view_controller.dart`) implements `packages/camera_api/STREAMING_GUIDE.md`'s LAN WebRTC path end to end — `GetWebRtcUri` discovery (`WebRtcUriClient`), offer/answer signaling over `package:flutter_webrtc`, no STUN/TURN (host candidates only, same-LAN), a grace window before an ICE `disconnected` blip is treated as a real drop, fresh-offer reconnect on a genuine drop, and a best-effort `POST /webrtc/stop` on teardown. WAN fallback isn't wired up here yet — LAN only. The Playback tab, and the Live tab for any camera with no saved connection, both still fall back to a bundled 15-minute dummy sample clip (`assets/videos/camera_dummy.mp4`) via the `video_player` package (see CLAUDE.md). Snapshot (LIVE-009) and Record (LIVE-010) are real for the real live feed too: snapshot calls `MediaStreamTrack.captureFrame()` directly on the remote video track (not a screenshot of the video widget, which is unreliable for a texture-backed `RTCVideoView`) and record uses `package:flutter_webrtc`'s `MediaRecorder` against that same track — both still save via the `gal` package into the device photo gallery. Falls back to the previous dummy-asset-trim behavior (`ffmpeg_kit_flutter_new`) when there's no real connection. Takes `homesController` and looks up the live `Camera` by id on every rebuild (via `ValueListenableBuilder`) instead of using a static navigation snapshot, so settings changed elsewhere (e.g. On-Screen Display's OSD toggles) are reflected immediately without leaving this screen. Also tracks the *phone's* own network type via `connectivity_plus` (LIVE-038/039/040) — a real, live-updating signal, independent of the camera's own Wi-Fi status shown elsewhere on this screen (LIVE-030). Privacy Mode and Video Mode also have quick-access shortcuts here (LIVE-041/042) so those two settings don't require a trip to Camera Settings — both call the real `camera_api` clients directly and apply immediately, unlike the full settings screens' draft-then-Apply convention.
