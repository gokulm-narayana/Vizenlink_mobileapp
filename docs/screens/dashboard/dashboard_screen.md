# DashboardScreen

- **Dart file:** `lib/screens/dashboard/dashboard_screen.dart`
- **Route:** `/dashboard`
- **Purpose:** Show the cameras belonging to the currently selected home, filterable by a flat row of tabs (All, Favourites, then one tab per room), with the ability to switch homes, favourite/pin/delete cameras via a long-press action menu, enter a dedicated reorder mode to drag cameras into a new order, and toggle between grid and list layout. Home/camera data is in-memory stub data for now (see `lib/app_state/homes_controller.dart`) — no backend wired up yet. Each camera tile also shows its own unread-alert count (DASH-014), backed by `lib/app_state/alerts_controller.dart`'s mock alert list.

## Elements

| Design ID | Element | Type | Notes |
|-----------|---------|------|-------|
| DASH-001 | Home selector (AppBar title) | PopupMenuButton | shows current home name with a dropdown chevron; tap opens the home list |
| DASH-002 | Home list items (in dropdown) | PopupMenuItem | one per home; tap switches the selected home |
| DASH-003 | "Manage homes" entry (in dropdown) | PopupMenuItem | navigates to `/homes/manage`; separated from home list by a divider |
| DASH-018 | "Done" button (AppBar action) | TextButton | only shown while reorder mode is active (entered via DASH-016's "Rearrange cameras"); tapping exits reorder mode, returning tiles to their normal tap/long-press behavior |
| DASH-019 | Add camera button (AppBar action) | IconButton | shown whenever reorder mode is not active (replaces DASH-018 in that state); shows the real scanning popup (SCAN-001) directly over the Dashboard — cancelable via SCAN-002/back gesture, confirmed by SCAN-014 — and only navigates to `/dashboard/scan` once that scan actually completes, passing its results along so that screen doesn't re-scan (see [scan_cameras_screen.md](../scan/scan_cameras_screen.md)). |
| DASH-008 | Collection tab bar | Scrollable TabBar | below the AppBar; tabs are `All`, `Favourites`, then one tab per distinct room name in the selected home (alphabetical), then `Unassigned` if any camera has no room |
| DASH-004 | View toggle button | IconButton (pinned to the trailing edge of the tab bar row) | switches camera layout between full-width grid (1 column) and list; stays visible across every tab, tabs scroll underneath it |
| DASH-005 | Camera collection | `ReorderableListView.builder` (single column in both layouts) | renders one CameraTile per camera in the active tab's filtered set (All = every camera, pinned first; Favourites = favourited only; a room tab = cameras in that room). Outside reorder mode, `buildDefaultDragHandles: false` and tiles handle their own tap/long-press (drag is inert); in reorder mode, `buildDefaultDragHandles: true` and each tile's tap/long-press are disabled so a plain long-press-and-drag anywhere on the tile reorders it (Flutter's default mobile `ReorderableListView` gesture — no visible handle). Dropping persists the new order into `home.cameras` via `HomesController.reorderCamera`, so the order carries across tabs and the grid/list toggle. Reorder mode applies to whichever tab is active when entered, and to every tab (not just All) |
| DASH-006 | Camera tile | CameraTile (custom widget) | full-width thumbnail; camera name + a status dot overlaid on top of the image (green/amber/red for Online/Needs Attention/Offline, from `Camera.liveStatus`), plus a small amber pin glyph (bottom-right of the thumbnail) when the camera is pinned. When offline: darkened overlay centered on the thumbnail showing "Camera Offline" and, if known, "Last seen <relative time>" (e.g. "Last seen 2h ago"); the compact list-layout thumbnail shows just the offline icon with the same text as a tooltip (too small to fit the full text). Outside reorder mode, long-press opens the DASH-016 actions menu and the tile shows a primary-color border for as long as that menu is open; in reorder mode, a small non-interactive drag-indicator icon appears top-right (grid) or trailing (list) as a visual cue, and tap/long-press are disabled |
| DASH-014 | Unread alert count badge | Small pill badge (solid red `#EF4444`, white numeral, themed border ring, drop shadow) overlaid top-left on the tile's thumbnail (grid) or its small thumbnail (list) | shown only when `AlertsController.unreadCountForCamera(camera.id) > 0`; displays the count, capped at "9+"; mock data for now, no backend wired up yet |
| DASH-021 | Health/attention icon | Amber warning-triangle icon | shown when `camera.needsAttention` is true (derived from `Camera.healthConditionMessages` — currently a storage-failure condition and/or a worn-out SD card, see [storage_screen.md](../camera_settings/recording_and_storage/storage_screen.md)). Grid layout: top-right of the thumbnail, hidden while that corner shows the reorder-mode drag indicator instead. List layout: inline next to the status dot. Tap-through detail lives on [camera_info_screen.md](../camera_settings/camera_info_screen.md)'s Health section, not on the tile itself |
| DASH-016 | Camera actions menu | Bottom sheet (glass-carded), opened via long-press on a DASH-006 tile (outside reorder mode) | lists: "Rearrange cameras" (`DASH-016-rearrange`, enters reorder mode — see DASH-005/DASH-018), Add/Remove favourite (`DASH-016-favorite`), Pin/Unpin (`DASH-016-pin`, only shown on the All tab), and Delete camera (`DASH-016-delete`, offline/danger-tinted). Delete opens a confirm `AlertDialog` ("Delete camera?" / Cancel / Delete) before calling `HomesController.deleteCamera`; Favourite and Pin apply immediately via `HomesController.toggleFavorite` / `togglePin` |
| DASH-007 | Empty state | Text | shown when the active tab's camera collection is empty |
| DASH-020 | Assistant button (FAB) | `GradientFab` (custom widget, solid cyan fill) | opens the [camera_chatbot.md](camera_chatbot.md) floating chat overlay (`showCameraChatbot`), a stub/mock assistant that answers questions with recent events, video-clip cards, and camera snapshots. Extended (icon + "Ask AI" label) by default; collapses to an icon-only circle while the user scrolls down through an already-populated camera collection (`NotificationListener<UserScrollNotification>` around the `TabBarView`, tracked once at the Dashboard level so it reacts to whichever tab is currently active) and re-expands on scrolling back up — never fully hidden, always one tap away |
| DASH-022 | Multiview button | IconButton (pinned to the trailing edge of the tab bar row, after DASH-004) | opens [multiview_screen.md](../multiview/multiview_screen.md) for the currently selected home as a modal takeover (`Navigator.of(context, rootNavigator: true).push`, not a go_router route — same pattern as camera_live_screen.md's fullscreen/AI Mode, so it renders outside MainShell's bottom nav bar) — a dedicated watch-all-cameras-at-once grid, distinct from this screen's own DASH-004 grid/list layout toggle (which is for browsing/navigating to a single camera, not simultaneous live viewing) |
| DASH-023 | Force LAN/WAN test menu (AppBar action, leading edge of `actions`) | `PopupMenuButton<LiveViewTransport?>` (bug-report icon; turns orange/amber whenever a non-`null` override is active) | **Dev/test tooling only** — mirrors the sibling `nuraeye-rt` app's own Force LAN/WAN menu. Options: "Auto (normal behavior)" (`null`), "Force LAN (all cameras)", "Force WAN (all cameras)". Sets `DebugTransportOverride.instance.value`, a single global (not per-camera, not per-screen) choice read by every `LiveViewController` this app constructs — [camera_live_screen.md](../camera_live/camera_live_screen.md)'s live session and every [multiview_screen.md](../multiview/multiview_screen.md) tile. `CameraLiveScreen` also listens for a change while already open and reconnects fresh under the newly-selected transport. `Force WAN` skips the LAN attempt entirely (and stops WAN health-checks from ever switching back to LAN just because the camera happens to be reachable there); `Force LAN` stops the automatic WAN fallback on a LAN failure. Exists specifically to exercise WAN code paths (settings screens, live view) without physically moving the phone off the camera's LAN. Remove this menu, `DebugTransportOverride`, and `LiveViewController.forceTransport` together if WAN testing no longer needs a manual override. |

DASH-011 (previously an always-visible favourite-star IconButton on each tile) and DASH-015 (previously an always-visible pin IconButton) are retired — both actions moved into the DASH-016 long-press menu. DASH-017 (previously a separate always-visible drag-handle icon, wrapped in `ReorderableDragStartListener`) is also retired — it conflicted with the tile's own long-press gesture recognizer (both listened on the same pointer, so drags frequently failed to start) and was replaced by the DASH-016 "Rearrange cameras" → dedicated reorder-mode flow described above. DASH-012 (previously the FAB's "Add Camera" role) is retired — that action moved to the DASH-019 AppBar button, freeing the FAB slot for DASH-020's assistant.
